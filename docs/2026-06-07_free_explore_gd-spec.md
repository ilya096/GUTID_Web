## 1. Саммари фичи
- Что это: свободное перемещение по залу в режиме first-person с коллизиями и возможностью переключения в orbit-режим
- Для кого: студенты, выпускники, абитуриенты, гости университета
- Какую проблему решает: возможность самостоятельно осматривать экспонаты без жёсткого маршрута
- Ожидаемый эффект: игроки сами выбирают, какие объекты исследовать

## 2. Бизнес-контекст
- Почему фича появилась: core-цикл "свободный explore" — альтернатива аудио-туру
- Почему сейчас: после реализации hall_environment
- Какие альтернативы рассматривались: только first-person, только orbit — выбран гибрид
- Почему выбранный подход: игрок может переключаться между режимами для комфорта

## 3. Цели
- Главная цель: плавное перемещение без коллизий сквозь стены
- Вторичные цели: переключение между first-person и orbit режимами
- Что НЕ является целью: продвинутое физическое взаимодействие
- Почему цели сформулированы именно так: фокус на базовой навигации для исследования зала

## 4. Метрики успеха
- Основная метрика: % сессий с переключением режимов
- Дополнительные: среднее время исследования зала
- Guardrail-метрики: fps (< 15 — провал), потряснные сессии (< 2%)
- Горизонт оценки: через 24 часа после релиза
- Порог успеха/провала: fps < 15 — провал
- Почему выбраны именно эти метрики: напрямую отражают удобство навигации

## 5. Позиционирование в системе проекта
- Место в кор/мета-цикле: core loop, early stage
- Этап игрока: early (первая сессия)
- Какие системы использует: hall_environment, web_player
- Какие системы может затронуть/сломать: object_interaction (приближение к объектам)

## 6. Scope (In / Out / Future)
- In scope: first-person управление (WASD + мышь), orbit-режим (правой кнопкой), переключение F, коллизии со стенами
- Out of scope: продвинутый физический движок, прыжки, полёт
- Future (v2): мобильное управление (сенсорные жесты)
- Ключевые зависимости: hall_environment
- Почему границы scope проведены именно так: минимальная рабочая навигация для MVP

## 7. Use Cases / УФЧ
### 7.1 Первый вход
- Триггер: игрок завершил загрузку hall_environment
- Действия игрока: ничего (автоматический режим first-person)
- Реакция системы: включение управления, блокировка курсора
- Результат: игрок может двигаться по залу

### 7.2 Переключение режима
- Триггер: нажатие F
- Действия игрока: клавиша F
- Реакция системы: переключение между first-person и orbit
- Результат: курсор разблокирован/заблокирован

### 7.3 Негативные сценарии
- fps < 15: плашка "обнаружена низкая частота кадров"
- Ошибка коллизий: игрок может протиснуться сквозь стену

## 8. Сущности
- **PlayerController**:
  - Назначение: управление игроком и переключение режимов
  - Параметры: move_speed (3 м/с), look_sensitivity (0.1)
  - Состояния: first-person, orbit
  - Жизненный цикл: init → (switch_mode) → update position
  - Связи: hall_environment, usePlayerStore

- **MovementSystem**:
  - Назначение: расчёт движения и коллизий
  - Параметры: collision_distance (0.5м)
  - Состояния: idle, moving, colliding
  - Связи: physics_simple

## 9. Логика работы
- Условия запуска: loaded hall_environment
- Основной цикл: игрок двигается → проверка коллизий → рендер
- Правила прогресса: отсутствуют
- Правила наград/ограничений: отсутствуют
- Ошибки/исключения: потеря WebGL контекста, потеря фокуса окна

## 10. UI/UX
- Точки входа: автоматический после hall_loaded
- Ключевые состояния UI: loading screen → 3D зал
- Empty/Error/Loading/Success: loading screen → free explore
- Ключевые CTA: отсутствуют (свободный режим)

## 11. Параметризация / Конфиги
- `move_speed`: float, 3, диапазон: 1-10, где хранится: config.json
- `look_sensitivity`: float, 0.1, диапазон: 0.01-0.5
- `collision_distance`: float, 0.5, диапазон: 0.1-2.0

## 12. Формулы, Баланс-Переменные И Локализация
- Переменные баланса:
  - `move_speed`, `look_sensitivity`, `collision_distance`

## 13. Контекстные системы
- hall_environment: использует карту зала для коллизий

## 14. Аналитика и трекинг
- Event map: mode_switched, position_changed, fps_drop
- Обязательные параметры: mode, position, fps_value

## 15. Edge Cases и исключения
- Потеря фокуса: курсор разблокирован, управление паузится

## 16. Риски и митигации
- Технические: задержка ввода — оптимизировать raycast
- UX-риски: запутанность переключения режимов — инструкция в первом заходе

## 17. Acceptance Criteria / QA
- Управление работает (WASD + мышь)
- Переключение F работает
- Коллизии не позволяют проходить сквозь стены

## 18. План релиза

- Rollback plan: отключение флага
